# 拆门：用实际行为判断每一道门

在用户要求拆门、正常流程被拦、合法重试失败或局部成功被误判时按需使用。这是调查工具，不是每张票的前置检查、审批或发布门槛。先读本仓 AGENTS.md，复用现有结果与权限。

1. 从真实入口追到结果和清理。沿成功、失败后已提交、结果未知及可安全重试的路径，找齐所选范围内每个会拦截、延迟、要求手工补材料或悄悄降级的判断。记代码位置、触发条件、当前环境与这一层的责任；不要把普通运行故障或过时测试自称为安全门。
2. 对每道门先列上游已做的判断，指出它保护的对象、尚未覆盖的具体风险，以及同一输入下有门和无门时可观察到的差异。上游若已可靠保证同一事实、该边界不可绕过且失败语义等价，就不在本层再查一次。独立入口或不同信任边界不可仅因字段相同而当作重复。
3. 只认现有日志、可追溯代码契约或最小可复现对照。比较延时、额度、人工步骤、恢复复杂度及影响范围。能证明有独立作用且代价合理则保留；能证明重复且删除不丢保护则合并或删除；作用真实但代价过高则收窄。只有「应该」或未验证假设，最多记 TODO；不新增拦截。遇既有唯一或外部强制保护，证据不足时不盲删，也不把调查转成一层新审批。
4. 修改真正拦住流程的最小根因，优先复用唯一可信来源。用最少的相关用例验证正常流程恢复、必要拒绝依然有效、未知结果不会诱发重复动作。确定性步骤用命令或测试脚本，不依靠每次人工拼材料或 Agent 临场研判。不要隐藏错误、扩大权限、调高阈值或伪造记录来换通过。
5. 每道门用一行交代：位置/环境、上游已有内容、实际差异及证据、代价、保留/收窄/删除/TODO。只附必要的执行与清理结果，区分验证过、推测和未测；局部测试通过不等于实机闭环。
